Before the presentation

Run this 15–30 minutes before you present. It warms the build, warms the regression demo, builds the gallery, opens the simulator, VS Code, the GitHub tabs and the slides. Every command runs in Terminal, from the project folder.

The quick way: one command

Runs every step below in order, explains each one as it runs, and ends on main. About 5–8 minutes.

cd ~/Desktop/Task && scripts/presentation/prepare.sh
You'll see at the end: "All steps passed. You're ready." (The regression step prints a failure on purpose: that's the bug the demo catches.)

Or step by step

1. Go to the project, on the correct code

Moves into the project folder. Every other command runs from here.

cd ~/Desktop/Task

Switches to the correct code and fetches the latest version from GitHub.

git checkout main && git pull

Should say "nothing to commit, working tree clean".

git status

2. Warm up the build and confirm everything is green

Builds the project and runs all screenshot and logic tests (1–2 min the first time). Must end with "no snapshot failures". After this, the live run on slide 4 takes ~40 s.

make ios-test

3. Warm up the regression demo (it fails on purpose)

Builds the bug branch once, so the live demo on slide 6 is quick. It fails on purpose (29 failures); the last part switches back to main.

git checkout demo/regression && make ios-test ; git checkout main

4. Build the page you'll open on slide 5

Creates artifacts/gallery/index.html: every golden on one page.

make gallery

5. Start the simulator with the app

Builds the app, boots the pinned simulator and opens it (first time ~1.5 min). After this, ios-run on slide 9 takes ~15 s.

make ios-run

6. Open the windows you'll switch between

Opens the project in VS Code, so files open instantly during the talk.

open -a "Visual Studio Code" .

Opens the browser tabs for slides 7 and 11.

open https://github.com/SaadiIftikhar/newsdemo-screenshot-testing/pull/1 https://github.com/SaadiIftikhar/newsdemo-screenshot-testing/pull/2 https://github.com/SaadiIftikhar/newsdemo-screenshot-testing/actions

Opens the deck in PowerPoint.

open presentation/Presentation.pptx

Checklist

Rules for the live parts

  • Say what you're about to show before you run the command.
  • The red test on slide 6 is the point: say "this is supposed to fail" before you run it.
  • Never run make ios-record live: it rewrites the goldens.
  • Always end the demo with git checkout main.
  • If something breaks, don't debug it in front of them: use the fallback written under that slide.
