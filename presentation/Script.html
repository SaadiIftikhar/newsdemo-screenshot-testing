Part 1 · The problem

1

Cover: Catching visual bugs before readers do

0.5 min
Say

Hi, I’m Saad. Instead of a long slide show, I’ll mix a few slides with the real project: the app in the simulator, the code, and the tests running live. The question I’m answering: how do we catch visual bugs in the BILD and WELT apps, like a PLUS badge that silently disappears, before a reader sees them, when the news on screen changes every minute?

2

Every screen, in every state, on every app

1 min
Say

Start with the scale. Four apps, two platforms, dozens of screens, and every screen has states: loaded, empty, error, offline, logged in or out, premium or free. Then light and dark, different font sizes, phone and tablet. It multiplies fast. My small demo app alone has 89 approved pictures.

For you

89 = the number of approved screenshots (goldens) in this project. They come from 51 test functions, because one test usually records several variants (light, dark, largest font size).

3

Checking this by hand doesn’t scale

1 min
Say

Checking by hand is slow, it misses small things like a banner two points shorter, and live news gives you nothing stable to compare with. These bugs don’t break any logic, so normal tests stay green. Only readers notice. My answer has two parts: screenshot tests, and frozen fake data.

Switch to VS Code: In the code

3 min
Show / do

    ios/NewsKit/Sources/the app’s code (feed, paywall, account, games)
    ios/NewsKit/Tests/NewsUISnapshotTests/the screenshot tests, one file per area

  2. The fake data: Cmd+P → feed_default.json. Scroll to "id": "tsr-002" and point at "premium": true: that’s the PLUS article.
  3. One test: Cmd+P → FeedScreenSnapshotTests.swift, the first function test_feed_default. Then ComponentSnapshotTests.swift → test_teaserCard_premium (explained under “Tests explained” below).
  4. Its goldens: in the Explorer open __Snapshots__/FeedScreenSnapshotTests/ and click test_feed_default.light.png, .dark.png and .light_xxxl.png (VS Code shows the picture).
  5. All goldens on one page:
    open artifacts/gallery/index.html

    Opens the gallery setup.sh built: all 89 approved pictures, grouped by test, variants side by side.

Say

Everything is in one repository. Fixtures are the fake data, shaped exactly like the real API: this item is the PLUS article. This is a whole test: one line builds the real feed screen with that data and compares it with an approved picture. No app launch, no tapping: you don’t navigate to a screen, you create it in the state you want. These are its approved pictures, in light, dark and the largest font size, stored in git so every change to them is reviewed like code. And here are all 89 on one page.

For you

The test name decides the picture’s file name: test class + function + variant → __Snapshots__/FeedScreenSnapshotTests/test_feed_default.dark.png. That’s how a test finds its golden; no list or config file. If the file doesn’t exist, the test fails with “no golden”, which is how a new test is detected.

Optional, if there’s time: Cmd+P → feed_hostile_content.json (messy CMS text: HTML entities, line breaks, emoji, an hour-long video), then show it in the app:
make ios-run FIXTURE=feed_hostile_content

Relaunches the app with that fake data: clean headlines, “Noch keine Einträge”, 1:02:03. Its screenshots are tested too.

7

What happens when it runs

1 min
Say

Here’s one run. make ios-test boots the pinned simulator in the background. For each test: load the fake data, build the real view, freeze the clock, language and images, draw it in memory in each variant, find the golden by name, and compare. Same: pass. Different: fail, and the new picture is saved so a report can show exactly what changed.

For you

Where each step lives: fake data is loaded by FixtureStore.swift; freezing and drawing happen in SnapshotSupport.swift (the helpers assertScreen and assertComponent); comparing and naming are done by the open-source library swift-snapshot-testing. Failed pictures go to artifacts/ios/failures/; scripts/diff-report.swift turns them into the diff page.

8

The news changes. The test data never does.

1 min
Show / do

Optional: Cmd+P → FixtureStore.swift → FixtureEnvironment (the pinned clock, de_DE, Europe/Berlin).

Say

This is the key decision. A golden belongs to fake data, not to live news. Everything that could make two runs different is frozen: the data, the clock, language and time zone, images, animations, random numbers, the device. “vor 9 Min.” stays “vor 9 Min.” forever. So when a picture changes, the only possible reason is that the code changed, and nobody learns to ignore red. Real API changes are caught separately, by contract tests.

For you

The clock is fixed at 5 Nov 2026, 15:13 Berlin time. “Contract tests” check the fixtures still decode the way the real API’s data does (NewsCoreTests/FixtureContractTests.swift).

Part 5 · Team workflow and CI

12

The normal flow: nothing changed on screen

1 min
Say

This is most pull requests. Developer: change the code, optionally run the tests locally, open a pull request. CI starts by itself with two jobs in parallel: one checks no golden is blank and builds the gallery, the other runs all tests on GitHub’s Mac. All green. Reviewer: normal code review, no design sign-off because no picture changed, merge. Nobody does anything extra.

For you

The pipeline is .github/workflows/screenshots.yml. Jobs: lint-goldens, ios, and report (the bot comment). CI tests the merge result (the code as main will look), and runs again after the merge.

13

When a picture changes, a person decides

1 min
Say

When a picture changes, CI fails and reports it: a diff report and one bot comment saying how many changed and what kind. Then a person decides. A bug, the amber path: fix the code, CI runs again, then merge; the goldens never change. Intended, like a redesign, the purple path: add the record-snapshots label; CI re-records on its own machine, proves the new pictures and pushes them; CI verifies again; a design or QA owner approves the new pictures; then merge.

For you

The label is called record-snapshots. The bot commit is “chore(snapshots): re-record iOS goldens”. On GitHub, PR #1 is the regression (blocked) and PR #2 a redesign that went through the purple path; you can show them if asked:

open https://github.com/SaadiIftikhar/newsdemo-screenshot-testing/pulls?q=is%3Apr
14

Two rules that never bend

0.5 min
Say

One: goldens only come from CI, never from a laptop, because a different machine draws slightly different pixels. Two: approval is never automatic. A machine says what changed; only a person can say whether it was meant to. That’s also my rule for AI: it can sort and summarise, a human approves.

For you

Rule two is enforced by .github/CODEOWNERS: any change under __Snapshots__ needs design/QA approval.

For you · Tests explained

The helper every test uses

assertScreen(view) (full screens) and assertComponent(view) (single components) live in SnapshotSupport.swift. For each variant (light, dark, largest font size, unless the test picks fewer) they: freeze the clock, language, time zone, images and animations; draw the view in memory at a fixed size; then call the library’s assertSnapshot, which finds the golden by name and compares. Invisible noise is allowed (perceptual precision 0.98); anything visible fails.

1 · test_feed_default: the whole feed

// FeedScreenSnapshotTests.swift
func test_feed_default() throws {
    assertScreen(FeedView(state: .loaded(try Snap.store.feed("feed_default"))))
}
  • Snap.store.feed("feed_default") loads fixtures/feed/feed_default.json and decodes it with the app’s real decoder.
  • .loaded(...) is the state “the feed loaded fine”. Other tests pass .loading, .empty or an error instead: that’s how they reach other states without navigating.
  • FeedView is the app’s real feed screen.
  • No variants given, so all three are recorded: test_feed_default.light.png, .dark.png, .light_xxxl.png.

2 · test_teaserCard_premium: the PLUS card on its own

// ComponentSnapshotTests.swift
override func setUp() async throws {
    feed = try Snap.store.feed("feed_default")      // runs before every test
}

/// WELT-style paywalled item: the PLUS badge must survive refactors in both themes.
func test_teaserCard_premium() throws {
    assertComponent(TeaserCard(teaser: try teaser("tsr-002", in: feed)))
}
  • teaser("tsr-002", in: feed) picks the article with that id from the fixture: the Tesla PLUS article ("premium": true).
  • TeaserCard is the real card component used in the feed. Testing it on its own gives a small, clear picture when it breaks.
  • This is the test that catches the missing badge in the live demo.

3 · test_feed_offlineCached: offline, with articles still shown

/// Offline after a successful load: the cached feed stays on screen with "Stand 15:02 Uhr" on top,
/// instead of an error screen replacing the news.
func test_feed_offlineCached() throws {
    let since = FixtureEnvironment.now.addingTimeInterval(-11 * 60)
    assertScreen(FeedView(state: .stale(try Snap.store.feed("feed_default"), since: since, reason: .offline)),
                 variants: [.light, .dark])
}
  • since = the frozen clock minus 11 minutes, so the banner always says “Stand 15:02 Uhr”.
  • .stale(..., reason: .offline) is the state “we have saved articles, but the connection dropped”. No real network is turned off: the state is simply passed in.
  • Only light and dark here: the variants are chosen per test.

4 · test_login_wrongCredentials: a state reached by running real logic

// AccountSnapshotTests.swift
func test_login_wrongCredentials() async {
    let model = AccountViewModel(client: .demo, email: AuthClient.demoEmail, password: "falsch123")
    await model.signIn()
    assertScreen(AccountScreen(model: model), variants: [.light])
}
  • Creates the login screen’s model with a wrong password and calls the real signIn() against a fake login service (.demo, no network).
  • The model ends in the “failed” state, and the picture shows the error message: “E-Mail-Adresse oder Passwort ist falsch.”
  • So a screenshot test can also reach a state by running real code, still without the app or a server.
