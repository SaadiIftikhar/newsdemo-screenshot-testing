The normal flow: no visual change

What happens when a developer pushes a change that doesn't alter how any screen looks. This is most pull requests: bug fixes, refactors, new logic.

Step by step

Developer

1Change the code

Work on a branch as usual. Before pushing, make ios-test runs every screenshot and logic test locally in under a minute. It's optional, because CI runs the same tests anyway.

Developer

2Push and open a pull request

A pull request asks for the change to be merged into main. Opening it, or pushing new commits to it, starts CI automatically.

GitHub CI

3Two jobs run in parallel

lint-goldens checks that no golden is blank or broken, and builds a gallery of all goldens. ios runs on GitHub's Mac with the pinned simulator: all screenshot and logic tests (the same as make ios-test), then the UI tests that tap through the real app.

CI tests the merge result: the code as main will look after merging.

GitHub CI

4Everything is green

Every new picture matches its golden and every other test passes. The pull request shows a green check. If the bot commented earlier, it updates the same comment to "✅ Screenshot tests passed".

Reviewer

5Normal code review

A colleague reviews the code as usual. No golden image changed, so design/QA approval isn't needed.

Reviewer

6Merge

The change goes into main. With a merge queue, CI re-checks it against the latest main first, so two green pull requests can't break main together. After the merge, CI runs once more on main as confirmation.

In short: nobody has to do anything extra. The screenshot tests run on their own, and when nothing visual changed they stay green and out of the way.
